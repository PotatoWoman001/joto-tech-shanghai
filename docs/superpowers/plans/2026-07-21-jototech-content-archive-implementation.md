# JOTOTECH 全站内容采集中文实施计划

> 本文件是给业务负责人审核的中文执行版。程序文件、测试代码和命令级步骤保存在同目录的《技术执行附录》中。

## 一、最终目标

在完全不修改原网站 `https://www.jototech.cn/` 的前提下，以只读方式完成一次全站内容归档。

本次要得到的不是旧网站源代码，也不是旧页面视觉复制品，而是一份可以长期保存、方便检查、可以导入未来新后台，并且可以交给 AI 重新生成前端的“内容母库”。

内容母库必须做到：

- 原站公开页面先全部发现，避免遗漏。
- JOTO AI、JOTO.AI、Dify 相关页面全部排除。
- 其他正式页面、历史文章、旧产品页面和未放入当前导航的页面全部保留。
- 历史页面只保存内容，暂时不进入新站导航。
- 原文和原语言保持不变，不擅自改写。
- 原站存在的文字、邮箱、电话、地址或年份问题单独列出。
- 图片和文件脱离 `goodq.top`，保存到我们自己的内容母库。
- 优先取得旧站公开可获得的最高分辨率图片。
- 每条页面、图片、文件和错误都有清单，不能静默遗漏。

## 二、本阶段不做的事情

以下内容明确延后，不影响本次内容归档：

- 不修改或关闭原网站。
- 不复制旧网站 PHP 源代码。
- 不复制旧数据库。
- 不确定新数据库和 CMS。
- 不制作新网站视觉设计。
- 不实现新联系表单的邮件和入库功能。
- 不复制旧 Agify 账号、脚本和配置。
- 不配置新域名和新 IP。
- 不实施新站 SEO。

这些事项会在内容母库验收后分阶段完成。

## 三、整体流程

```text
原网站（只读）
    ↓
发现 Sitemap、导航和页面内部链接
    ↓
先排除 JOTO AI / JOTO.AI / Dify
    ↓
小范围试采集并检查
    ↓
全站页面、文章、图片和文件采集
    ↓
正文拆成结构化内容
    ↓
生成 JSON、Markdown、HTML 和截图
    ↓
生成页面、资源、错误和问题清单
    ↓
自动对账 + 人工逐页复核
    ↓
交付内容母库
```

## 四、页面如何分类

每个发现的地址都会有明确状态：

| 状态 | 中文含义 | 新站默认处理 |
|---|---|---|
| `active` | 当前正式页面或导航页面 | 保留，可进入新导航 |
| `archived` | 历史页面、旧产品页、未进入当前导航的页面 | 保留内容，不进入新导航 |
| `duplicate` | 与其他页面内容相同的旧地址 | 保留证据并记录重复关系 |
| `excluded-ai` | JOTO AI、JOTO.AI 或 Dify 页面 | 不采集，不进入内容母库 |
| `resource` | 图片、PDF、Word、Excel、PPT、压缩包等 | 进入资源库，不当成网页 |
| `external` | 外部网站地址 | 记录链接；公开文件按规则下载 |
| `unreachable` | 原站本身无法打开 | 记录状态和证据 |
| `error` | 可以访问但采集过程出现错误 | 重试并进入错误清单 |

## 五、AI 与 Dify 如何保证删干净

排除分为两层。

### 第一层：根据地址直接排除

以下情况在打开页面正文之前直接排除：

- 已知 JOTO AI 页面 ID，例如 `page_id=15197`。
- 地址中包含 `joto-ai`。
- 地址中包含 `jotoai`。
- 地址中包含 `dify`。
- 人工加入排除名单的地址。

### 第二层：数字地址标题预检

部分历史页面只有 `?p=数字`，从地址看不出内容。

对这种地址只进行一次标题级预检：

- 只检查网页标题和公开标题元数据。
- 如果标题包含 JOTO AI、JOTO.AI 或 Dify，立即排除。
- 不生成正文、HTML 存档、截图或页面资源。
- 只在排除清单记录地址和排除原因。

普通页面顶部导航里出现“JOTO AI Solution”不会导致整页被误删，因为预检只检查页面自身标题，不检查导航文字。

## 六、历史文章如何支持以后换格式

历史文章不会只保存为一整块旧 HTML，而会按原顺序拆成内容模块：

- 文章标题
- 副标题
- 正文段落
- 有序列表
- 无序列表
- 表格
- 引用
- 图片
- 图片说明
- 按钮和链接
- 视频或嵌入内容
- 下载文件
- 表单字段说明

例如一篇旧文章会变成：

```text
文章标题
  1. 标题模块
  2. 正文段落
  3. 二级标题
  4. 图片模块
  5. 图片说明
  6. 表格模块
  7. 下载按钮
```

以后 AI 生成新前端时，文章内容不需要重抓，只需要建立新的文章模板。一次修改模板，就能统一更新所有历史文章的字体、间距、宽度、图片布局、表格样式和手机端排版。

为了防止结构化时少内容，每篇文章还会保留：

- 原始 HTML
- 桌面端全页截图
- 手机端全页截图
- 原始来源地址

## 七、图片清晰度处理规则

每张图片都会检查多个可能来源：

- 页面中的普通图片地址。
- 延迟加载图片地址。
- `srcset` 中的高清版本。
- CSS 背景图。
- 浏览器实际加载的图片资源。
- `goodq.top` CDN 地址背后编码的原上传地址。
- WordPress/起飞页生成的不同尺寸版本。

如果页面引用的是：

```text
photo-150x150.jpg
photo-300x200.jpg
photo-1024x683.jpg
photo.jpg
```

系统会优先尝试 `photo.jpg`，并比较真实像素尺寸，保存公开可获得的最高质量版本。

图片归档规则：

- 不进行二次有损压缩。
- 不人为放大低清图片。
- 原图与未来生成的 WebP、AVIF、缩略图分开保存。
- 相同图片只保存一份，但记录它被哪些页面使用。
- 记录原地址、最终地址、文件名、格式、大小、宽度、高度和 SHA-256 校验值。
- 记录图片 Alt、标题、说明和页面位置。
- 找不到高清图时明确标记“旧站仅提供低分辨率版本”。
- 下载失败的图片不能跳过，必须进入 `asset-errors.csv`。

## 八、实施阶段

### 阶段 1：建立安全采集工具

要做的事：

- 建立独立项目目录和版本记录。
- 配置原站地址、Sitemap 地址和输出目录。
- 将采集并发限制为单线程。
- 每次公开请求至少间隔 750 毫秒。
- 设置最多三次有限重试。
- 限制工具只支持读取，不提供提交表单、登录或修改功能。

产出：

- 可重复运行的采集工具。
- 安全配置文件。
- 自动化测试。

验收：

- 工具只能使用 GET 读取公开资源。
- 不访问后台管理接口。
- 不提交联系表单。
- 不修改原站任何内容。

### 阶段 2：建立完整页面清单

要做的事：

- 读取公开 Sitemap。
- 读取首页和当前主导航。
- 读取页面内部同域链接。
- 持续发现页面，直到没有新地址。
- 合并 HTTP/HTTPS、尾斜杠、查询参数等地址差异。
- 保留重复地址和原地址关系。
- 将图片和文档地址识别为资源，而不是网页。

产出：

- 全部 URL 清单。
- 当前导航层级。
- 历史页面清单。
- 外部链接清单。
- AI/Dify 排除清单。

验收：

- Sitemap 每个地址都有处理状态。
- 当前导航每个入口都有处理状态。
- 页面中新发现的同域地址都有处理状态。
- 不允许出现“发现了但没处理”的地址。

### 阶段 3：AI/Dify 排除检查

要做的事：

- 应用已知页面 ID 排除规则。
- 应用 JOTO AI、JOTO.AI 和 Dify 地址关键词规则。
- 对无法判断的数字地址进行标题级预检。
- 建立排除清单。

产出：

- `exclusions.csv`

清单内容：

- 被排除地址
- 地址来源
- 命中的规则
- 排除原因
- 发现时间

验收：

- 被排除页面没有 JSON、Markdown、HTML 和截图。
- 被排除页面的专属图片和文件没有进入资源库。
- 同时被正常页面使用的共享图片仍然保留。

### 阶段 4：三页试采集

正式全站采集前，先选择三类页面：

- 一个当前导航页面。
- 一个历史或非导航页面。
- 一个图片和内容结构较复杂的页面。

要做的事：

- 保存服务器返回的原始 HTML。
- 使用真实浏览器渲染页面。
- 保存桌面端和手机端截图。
- 提取正文模块。
- 下载页面图片和文件。
- 生成试采集清单。

验收：

- 三个页面的正文顺序正确。
- 没有把导航和页脚误当正文。
- 图片位置和数量正确。
- 历史页面被标记为 `archived`。
- AI/Dify 页面没有被正文采集或存档；无法从地址判断的数字页面只允许标题级预检。
- 你确认试采集结果后才执行全站。

### 阶段 5：全站页面采集

要做的事：

- 按页面清单逐页读取。
- 保存原始 HTML。
- 保存桌面端全页截图。
- 保存手机端全页截图。
- 提取标题、正文、列表、表格、图片、按钮和下载文件。
- 记录页面内部链接和外部链接。
- 记录原表单字段和字段顺序。
- 单页失败不影响其他页面继续采集。

产出：

- 页面 JSON
- 页面 Markdown
- 页面原始 HTML
- 桌面截图
- 手机截图

验收：

- 每个允许采集且可以访问的页面都有五类输出。
- 无法访问或失败页面全部进入错误清单。
- 不能通过少报页面数量来实现“成功”。

### 阶段 6：图片和文件归档

要做的事：

- 下载正文图片、Logo、图标、背景图和轮播图。
- 下载 PDF、Word、Excel、PPT 和公开压缩包。
- 下载能够公开访问的外部文件。
- 解码 GoodQ CDN 原始资源地址。
- 尝试原图和不同尺寸版本。
- 校验图片是否可以正常解码。
- 计算 SHA-256。
- 按 SHA-256 去重。

产出：

- 图片资源库。
- 文档资源库。
- `assets.csv`
- `asset-errors.csv`
- 图片质量报告。

验收：

- 每个页面使用的资源要么成功保存，要么明确出现在失败清单。
- 图片宽度和高度可验证。
- 文件 SHA-256 与清单一致。
- 内容母库不依赖 `goodq.top` 才能查看资源。

### 阶段 7：原站内容问题检查

自动检查：

- 页面显示邮箱与 `mailto:` 是否一致。
- 页面显示电话与 `tel:` 是否一致。
- 图片是否丢失或低清。
- 内部链接是否失效。
- 页面是否重复。
- 页面是否没有正文。

人工检查：

- 拼写和语法问题。
- 公司名称是否一致。
- 地址是否过期。
- 电话和邮箱应该保留哪一个。
- 年份是否需要更新。
- 页面标题是否清晰。

处理原则：

- 原文完整保留。
- 不自动修正文案。
- 问题单独进入 `content-issues.csv`。
- 后续由你决定如何改。

### 阶段 8：完整性自动对账

每个页面自动统计：

- 标题数量
- 正文段落数量
- 列表数量
- 列表项数量
- 表格数量
- 图片数量
- 按钮数量
- 下载文件数量
- 表单和字段数量

同时检查：

- 页面 JSON 是否存在。
- Markdown 是否存在。
- 原始 HTML 是否存在。
- 桌面截图是否存在。
- 手机截图是否存在。
- 页面引用的图片和文件是否存在。
- 文件 SHA-256 是否正确。
- 被排除的 AI/Dify 页面是否错误地产生了内容文件。

产出：

- `content-counts.csv`
- `completeness-report.md`
- `crawl-report.md`
- `image-quality-report.md`

### 阶段 9：人工逐页复核

复核顺序：

1. 当前导航正式页面。
2. 历史文章。
3. 旧产品和旧行业方案页面。
4. 图片较多的页面。
5. 表格和下载文件较多的页面。
6. 自动检查标记异常的页面。

每页检查：

- 标题是否正确。
- 正文是否完整。
- 内容顺序是否正确。
- 图片是否缺失。
- 图片是否使用最高可得清晰度。
- 表格和列表是否完整。
- 按钮和链接是否记录。
- 桌面截图和手机截图是否对应。
- 页面状态是否正确。

## 九、项目检查点

### 检查点 A：规则确认

你检查：

- AI/Dify 排除规则。
- 页面状态定义。
- 历史页面默认不进入新导航。

当前状态：已确认。

### 检查点 B：三页试采集

你检查：

- 内容是否完整。
- 图片是否清晰。
- JSON/Markdown 是否方便后续使用。
- 截图是否能用于核对。

只有你确认后才进行全站采集。

### 检查点 C：全站自动验收

你检查：

- 页面总数和状态分布。
- AI/Dify 排除清单。
- 页面和资源失败清单。
- 图片质量报告。

### 检查点 D：人工筛选

内容母库完成后，你决定：

- 哪些历史页面进入新站。
- 哪些重复页面合并。
- 哪些内容删除。
- 哪些原站错误需要修正。

## 十、异常情况如何处理

| 异常 | 处理方式 |
|---|---|
| 页面临时无法打开 | 有限重试，仍失败则记录 |
| 页面返回 404/500 | 标记原站状态，不伪造内容 |
| 图片 CDN 地址失效 | 尝试解码原地址和其他尺寸 |
| 只有低清图 | 保存最高可得版本并标记 |
| 外部文件无法下载 | 保留外部地址并记录失败 |
| 页面结构无法识别 | 保存为 `unknown` 内容块并保留原 HTML |
| 两个地址内容相同 | 两个地址均记录，标记重复关系 |
| 邮箱或电话不一致 | 原文不改，进入问题清单 |
| 单页采集程序报错 | 记录后继续，不中断全站 |

## 十一、最终验收标准

项目只有满足以下条件才算完成：

- 所有公开发现的地址都有最终状态。
- 所有 AI/Dify 页面均被排除。
- 非排除且可访问的页面均有 JSON、Markdown、HTML 和两类截图。
- 历史页面保留内容，但默认不进入新导航。
- 页面正文、图片、列表、表格、按钮、链接和文件可追踪。
- 所有实际使用的公开资源成功归档或明确进入失败清单。
- 图片使用旧站公开可获得的最高质量版本。
- 原文没有被程序静默修改。
- 原站问题全部单独记录。
- 内容母库脱离 `goodq.top` 后仍能保存和管理资源。
- 将来可以不重新抓原站，直接适配新 CMS、数据库和 AI 前端。

这里的“全部完成”不是假设原站所有内容都能正常打开。如果原站本身已经丢失页面或文件，验收标准是准确记录丢失状态，而不是虚构恢复成功。

## 十二、内容母库完成后的后续顺序

1. 由你筛选正式页面和历史内容。
2. 确认原站问题如何修正。
3. 选择新 CMS、数据库和对象存储。
4. 将内容母库导入新后台。
5. 使用 AI 生成新前端和文章模板。
6. 重建联系表单和线索流程。
7. 使用新账号接入 Agify。
8. 配置新域名、新 IP 和 HTTPS。
9. 单独实施新站 SEO。

SEO 阶段会再次提醒处理：

- 新域名定位
- 页面标题和描述
- 新 URL 规则
- Sitemap
- robots.txt
- Canonical
- 图片 Alt
- 结构化数据
- 百度和 Google 收录
- 统计工具
- 新旧域名同时存在导致的重复内容问题
