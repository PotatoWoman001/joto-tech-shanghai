# JOTOTECH 全站内容采集与新站内容母库设计

日期：2026-07-21

## 1. 项目目标

在不修改、不停用原网站 `https://www.jototech.cn/` 的前提下，通过只读方式采集原网站的公开内容和公开资源，建立一份与具体前端框架、CMS、数据库、域名和服务器无关的结构化内容母库。

新网站将部署到新的域名和 IP。新网站的前端视觉由后续阶段重新设计，内容后台和数据库也将在后续阶段确定。本阶段不复制旧网站源码，不复用旧网站表单提交接口，不实施新站 SEO。

## 2. 已确认的业务范围

### 2.1 保留范围

- 先发现并采集原网站全部公开页面，再进行人工筛选。
- 页面发现来源包括公开 Sitemap、当前导航、页面内部链接和历史页面之间的链接。
- 采集当前导航中的正式页面。
- 采集旧版产品页面、历史文章、未进入当前导航的页面、重复内容的旧地址、测试页面及名称不清晰的页面。
- 历史页面和非导航页面进入内容母库，但默认状态为 `archived`，不进入新站导航。
- 保留原页面语言，不翻译，不改写正文。
- 原文中发现的拼写、邮箱、电话、地址、年份或链接冲突不直接修正；原样保存，并写入问题清单。

### 2.2 明确排除范围

- JOTO AI Solution 页面不采集。
- 所有 JOTO AI、JOTO.AI 和 Dify 相关页面不采集正文、HTML、截图或页面专属资源。若某项资源同时被非排除页面引用，则按非排除页面的正常资源处理规则归档。
- 被排除页面只在排除清单中记录 URL、命中规则和排除原因，用于证明筛选过程完整。
- 不复制旧 Agify 脚本和旧 Agify 配置。未来新站如需客服，使用新站自己的 Agify 账号重新接入。
- 不复制旧联系表单的提交接口、Session、Nonce、邮件配置或数据库行为。
- 不采集服务器端 PHP 源码、数据库、后台账号或非公开文件。
- 不修改原网站内容、配置、导航、DNS、域名、数据库或服务器。

### 2.3 延后范围

- 新站前端视觉设计与组件样式。
- 新 CMS 和新数据库的最终选型与实现。
- 新域名和新 IP 配置。
- 联系表单邮件投递、线索入库和反垃圾机制。
- 新 Agify 客服接入。
- SEO 关键词、标题描述、Canonical、结构化数据、搜索引擎提交和统计工具。

## 3. 旧站现状摘要

初步检查显示，旧站为起飞页 Qifeiye 托管的 WordPress 衍生 PHP/CMS 网站，前端使用服务端 HTML、jQuery、页面构建器和大量内联样式。公开 Sitemap 当前约有 73 条 URL，其中包含导航页面、历史内容、孤立页面、旧地址以及 JOTO AI/Dify 相关页面。

页面静态资源主要通过 `goodq.top` CDN 分发。联系页面使用旧 CMS 的 iPhorm/AJAX 表单，公开字段包括姓名、邮箱、电话、公司名称和需求描述。页面还加载了第三方 Agify 聊天脚本。

这些技术实现只用于判断内容和依赖关系，不作为新站需要复制的源代码架构。

## 4. 方案选择

采用方案 B：结构化内容母库。

每个页面同时保留机器可读内容、人工可读内容和原始证据：

- JSON：供程序、AI 前端和未来 CMS 导入器使用。
- Markdown：供人工审核和编辑正文。
- 原始 HTML：作为采集证据和遗漏复核来源，不作为新前端代码。
- 桌面端和手机端截图：用于核对区块顺序、图片位置和可见内容。
- 资源文件：保存站内使用的最高可得清晰度版本。
- CSV 清单：用于页面、资源、链接、问题和排除项的批量对账。

## 6. 页面发现与分类

### 6.1 发现顺序

1. 读取公开 Sitemap 中的 URL。
2. 读取首页和所有主导航链接。
3. 访问允许采集的页面，提取同域内部链接。
4. 对新发现的同域页面继续检查，直到没有新的公开页面。
5. 规范化 URL，识别参数地址、漂亮链接、HTTP/HTTPS 和尾斜杠差异。
6. 记录重复内容和地址别名，不因去重而丢失旧 URL。

### 6.2 页面状态

每条发现的 URL 必须具有且只具有一个处理状态：

- `active`：当前导航或当前正式内容页面。
- `archived`：需要保留内容，但不进入新站导航。
- `duplicate`：内容与其他页面重复，保留地址映射和采集证据。
- `excluded-ai`：命中 JOTO AI/JOTO.AI/Dify 排除规则。
- `external`：非 jototech.cn 页面，只记录外部引用。
- `resource`：公开图片、文档或压缩包等非 HTML 资源，由资源管线归档，不作为页面渲染。
- `unreachable`：在规定重试后仍无法公开访问。
- `error`：页面可访问，但解析、渲染或资源处理失败。

### 6.3 “未进入导航页面”的处理

未进入当前导航、但能从 Sitemap 或站内链接发现的页面，默认采集并标记为 `archived`。示例可能包括旧产品页、旧行业方案、Tech Blog、Device42、WellProcess、Data Security、MSP、Sport，以及名称类似“一个新页面”的历史内容。

这些页面是否进入新网站，由内容母库完成后的筛选阶段决定。

## 7. AI 与 Dify 排除规则

首先根据 URL 和已知页面标识执行排除检查。对于 `?p=数字` 等无法从 URL 判断主题的地址，允许进行一次只用于分类的标题级预检；预检响应不写入内容母库。如果 `<title>` 或 Open Graph 标题命中 JOTO AI/JOTO.AI/Dify，该页面立即进入排除清单，不进行浏览器渲染、正文解析、截图或资源下载。

排除条件包括：

- URL 或 slug 包含 `joto-ai`、`jotoai` 或 `dify`。
- 已知页面 ID 对应 JOTO AI Solution。
- Sitemap 标题明确表示 JOTO AI、JOTO.AI 或 Dify。
- 页面被人工加入 AI/Dify 排除表。

对可能误判的普通页面，不仅凭正文中偶然出现单词 “AI” 就整页排除。普通页面如果只在局部提到 AI/Dify，应保留页面原文，并在问题清单中标记该引用，待筛选阶段决定是否删除局部内容。

排除清单至少包含：

- URL
- Sitemap 或链接来源
- 命中规则
- 排除原因
- 发现时间
- 处理状态

## 8. 页面内容模型

每个页面保存一个稳定的页面标识，并保留来源 URL 与所有已知别名。

页面 JSON 顶层字段包括：

- `id`
- `sourceUrl`
- `sourceAliases`
- `sourcePageId`
- `title`
- `language`
- `status`
- `navigationPath`
- `breadcrumbs`
- `contentType`
- `blocks`
- `assets`
- `internalLinks`
- `externalLinks`
- `downloadLinks`
- `formDefinitions`
- `capturedAt`
- `contentHash`
- `issues`

### 8.1 语义区块

页面正文按原始顺序拆成语义区块。允许的基础区块包括：

- `heading`
- `paragraph`
- `richText`
- `image`
- `gallery`
- `list`
- `table`
- `quote`
- `testimonial`
- `caseStudy`
- `partner`
- `button`
- `download`
- `video`
- `embed`
- `contactDetails`
- `formDefinition`
- `separator`
- `unknown`

无法可靠识别的内容必须进入 `unknown` 区块并保留对应原始 HTML，不得静默丢弃。

### 8.2 历史文章

历史文章保存正文语义，不保存视觉样式作为内容的一部分。标题、段落、列表、表格、引用、图片、图注、链接和下载文件按照原页面顺序保存。

未来新前端通过统一文章模板渲染这些区块，因此可以集中更新字体、宽度、间距、图片布局、表格样式和移动端排版，而不需要逐篇修改正文。

## 9. 图片与文件策略

### 9.1 采集范围

- 正文图片
- Logo
- 图标
- 背景图
- 轮播图和图库图片
- CSS 中实际使用的背景资源
- PDF、Word、Excel 等公开下载文件
- 能公开下载的外部文件

外部网页本身不进行站外递归采集。外部文件下载后仍记录原始外部 URL 和来源页面。

### 9.2 最高可得清晰度

为每张图片检查：

- `src`
- `srcset`
- 延迟加载字段
- 页面构建器的数据字段
- CSS 背景地址
- CDN 地址中编码的原始上传路径
- WordPress/Qifeiye 常见尺寸后缀

当存在多个版本时，通过真实像素尺寸、文件大小和有效性选择最高质量版本。优先尝试无缩略图尺寸后缀的原始上传文件。

归档文件不进行二次有损压缩，不人为放大。若旧站只公开低分辨率文件，则保存最高可得版本，并在问题清单中标记缺少高清原图。

### 9.3 资源清单

每个资源记录：

- `assetId`
- 原始 URL
- 最终响应 URL
- 引用页面
- 页面中的用途和位置
- 原始文件名
- 建议安全文件名
- MIME 类型
- 文件扩展名
- 文件大小
- 图片宽度和高度
- 图片 Alt、标题和图注
- SHA-256 校验值
- 下载状态
- 清晰度判断
- 是否为外部资源

相同二进制文件只保存一份，但所有页面引用关系必须保留。原始资源与未来生成的 WebP、AVIF 或缩略图分开管理。

## 10. HTML、Markdown 与截图

### 10.1 原始 HTML

保存服务器返回的公开 HTML，作为证据和重新解析来源。原始 HTML 不作为新站的前端实现，不要求复制旧 CSS、JavaScript 或页面构建器行为。

### 10.2 Markdown

Markdown 保持正文语义和原顺序，方便运营人员阅读、校对和修改。无法在 Markdown 中完整表达的表格、嵌入或特殊区块，通过明确占位引用对应 JSON 区块，不得省略。

### 10.3 截图

对非排除页面至少保存：

- 一份桌面端全页截图
- 一份手机端全页截图

截图用于检查页面顺序和可见元素，不作为正文的唯一来源。

## 11. 导航和页面关系

保存原网站：

- 主导航顺序
- 下拉菜单层级
- 分类与子页面关系
- 页脚链接
- 面包屑
- 页面内部链接
- 重复 URL 和内容别名

历史页面可以保留其原分类关系，但默认不加入新站公开导航。

## 12. 表单和第三方功能

### 12.1 联系表单

只保存表单定义和页面位置，包括：

- 字段名称
- 字段顺序
- 必填状态
- 字段类型
- 按钮文字
- 成功或错误提示的公开文案

不调用或复制旧提交接口，不发送测试线索，不保存旧 Session、Nonce、邮件地址配置或后台行为。

### 12.2 Agify

记录旧站加载 Agify 的事实和脚本来源，但不将旧脚本或配置纳入新站内容。后续由新站使用自己的 Agify 配置重新接入。

### 12.3 其他第三方依赖

发现地图、视频、统计、客服、表单、字体或合作伙伴嵌入时，记录供应商、公开 URL、所在页面和用途。除明确要求归档的公开下载文件外，不复制第三方服务内部数据。

## 14. 完整性验证

### 14.1 URL 对账

- Sitemap 中每条 URL 都必须出现在 URL 清单。
- 导航中每个链接都必须出现在 URL 清单。
- 页面中发现的每个同域链接都必须具有处理状态。
- 每个 URL 必须归入成功、排除、重复、不可访问或错误之一。

### 14.2 内容对账

对每页记录并比较：

- 标题数量
- 段落数量
- 列表和列表项数量
- 表格数量
- 图片数量
- 按钮和链接数量
- 下载文件数量
- 表单数量和字段数量

结构化内容、Markdown、HTML 和截图之间出现明显数量差异时，页面不得标记为完成。

### 14.3 资源对账

- 每个页面引用的资源必须成功下载或进入失败清单。
- 每个下载文件必须通过 MIME、文件大小和 SHA-256 校验。
- 图片必须验证可解码并记录实际尺寸。
- CDN 原图、缩略图和重复文件关系必须可追踪。

### 14.4 人工复核

自动验证完成后逐页检查标题、正文顺序、图片位置、链接和截图。历史页面、内容异常页面、低清图片页面和包含复杂表格/嵌入的页面优先复核。

## 15. 错误处理

- 网络错误和临时服务器错误采用有限次数重试，并使用渐进退避。
- 不进行高并发或攻击性抓取，避免影响原网站。
- 页面失败后保存状态码、错误类型、时间和重试次数。
- 解析失败时仍保存已取得的 HTML 和截图，进入人工处理队列。
- 资源下载失败时不使用空文件替代。
- 不因单页失败中止整个采集任务。
- 所有最终失败项必须进入交付报告，不能静默遗漏。

## 16. 原站问题清单

发现以下情况时保留原文并记录：

- 显示邮箱与 `mailto:` 不一致
- 显示电话与 `tel:` 不一致
- 地址、公司名称或年份冲突
- 拼写和语法问题
- 空标题、空区块或无意义页面名
- 失效的内部或外部链接
- 缺失图片或低清图片
- 重复页面或重复正文
- 桌面端与手机端内容不一致

问题清单只提出证据和建议，不自动修改原内容。

## 18. 验收标准

- 所有发现的公开 URL 都有明确处理状态。
- 所有 AI/Dify 页面均被排除，不进入内容母库。
- 非排除且可访问的页面均具有 JSON、Markdown、HTML 和截图。
- 历史页面保留内容，但默认不进入新导航。
- 页面正文顺序、图片、列表、表格、按钮、链接和下载文件可追踪。
- 页面实际使用的公开资源均成功归档或明确列入失败清单。
- 图片使用旧站公开可获得的最高质量版本，不进行有损二次压缩。
- 原文不被静默修正，所有发现的问题进入问题清单。
- 内容母库不依赖 `goodq.top` 才能长期保存资源。
- 内容母库可在不重新抓取旧站的情况下适配未来 CMS 和新前端。

“公开页面抓取成功率 100%”的含义是：所有已发现 URL 均被处理并有最终状态；若原站本身返回错误、拒绝访问或资源已丢失，则必须完整记录，不能把源站不可用误报为采集成功。

## 19. 后续阶段提醒

内容母库验收后，再依次进行：

1. 内容筛选和原站问题修订。
2. 新 CMS、数据库和对象存储选型。
3. 编写内容导入器。
4. 使用 AI 生成新前端视觉和页面模板。
5. 重建联系表单及线索流程。
6. 使用新账号接入 Agify。
7. 配置新域名和新 IP。
8. 实施新站 SEO。

SEO 阶段必须专门处理新域名定位、页面标题描述、URL、Sitemap、robots.txt、Canonical、图片 Alt、结构化数据、百度/Google 收录、统计工具，以及新旧域名内容同时存在可能造成的重复内容问题。
