# JOTO Global 接入 admin.jotoai.com 设计

日期：2026-07-24

## 背景

`jotoglobal.com` 当前使用独立的联系表单服务：浏览器提交到同源
`/api/contact`，Nginx 再转发到 ECS 本机 `127.0.0.1:9000`，由该服务
直接发送邮件。留言不会进入 `admin.jotoai.com` 的统一留言列表，官网也
尚未接入后台现有的访客统计和站点健康巡检。

`admin.jotoai.com` 已提供以下可复用能力：

- 验证码生成与校验；
- 通用联系表单接收、留言存储、邮件通知和飞书同步；
- 跨站点留言聚合管理；
- 基于百度统计的访客统计；
- 基于后台站点配置的定时健康巡检、异常告警和每日报告。

## 已确认约束

- 联系表单切换后只走 `admin.jotoai.com` 统一后台，不进行双写。
- `xutomi3-art/jotoai-website-final` 后台仓库保持只读。
- 不修改、不提交、不部署后台仓库中的任何文件。
- 本轮只修改 `joto-site-v2` 官网、官网的 Nginx 配置和必要的部署配置。
- 后台站点登记、百度统计站点登记属于现有系统的运行时配置，不是后台
  仓库代码变更。
- 生产主域名仍为 `https://jotoglobal.com`。
- 表单继续支持英文、中文和波斯语，波斯语保持 RTL。

## 目标

- 新留言出现在 `admin.jotoai.com` 的统一留言管理页面，并以
  `jotoglobal.com` 标识来源。
- 新留言由统一后台负责邮件和飞书通知，官网本地联系服务不再承接生产
  提交。
- 官网访客数据进入后台现有访客统计体系，可按 `jotoglobal.com` 查看。
- 官网加入后台健康巡检清单，参与定时检查、异常告警和每日报告。
- 保持表单现有字段、三语言体验、反垃圾能力和失败兜底。
- 不影响服务器上的其他站点及 `admin.jotoai.com` 现有业务。

## 非目标

- 不重构或替换 `admin.jotoai.com` 后台。
- 不修改后台的站点注册表、留言模型、管理页面或统计实现。
- 不为官网建立新的数据库、统计平台或管理后台。
- 不把官网文章管理接入后台。
- 不删除当前仓库中的独立联系服务源码；该源码仅退出生产请求链路，保留
  作为历史记录和紧急回滚材料。

## 方案选择

采用“官网同源代理到现有通用后台接口”：

1. 浏览器从官网同源 `/api/captcha` 获取后台验证码。
2. 浏览器向官网同源 `/api/contact` 提交表单。
3. Nginx 把两个请求转发到 `https://admin.jotoai.com` 的同名接口。
4. Nginx 使用 `Host: admin.jotoai.com` 和对应 TLS SNI 访问正确的上游
   虚拟主机，同时设置 `X-Forwarded-Host: jotoglobal.com`，让后台按
   真实来源域名存储和展示留言。

未采用浏览器直接跨域请求后台，因为同源代理能避免 CORS、来源主机丢失
和浏览器侧暴露后台地址等问题。未采用旧服务转发或双写，因为会形成两个
邮件发送者和两套失败语义，增加重复通知及数据不一致风险。

## 架构与数据流

### 留言

```text
访客浏览器
  ├─ GET  https://jotoglobal.com/api/captcha
  └─ POST https://jotoglobal.com/api/contact
             │
             ▼
       jotoglobal.com Nginx
             │ 保留来源 Host
             ▼
       admin.jotoai.com
         ├─ 验证验证码
         ├─ 存储留言
         ├─ 发送统一邮件
         ├─ 同步飞书（已配置时）
         └─ 在留言管理页按来源展示
```

前端保留现有字段并提交以下后台兼容数据：

- `name`
- `company`
- `email`
- `phone`
- `phoneOrWechat`
- `message`
- `website`：现有隐藏蜜罐字段
- `captchaId`
- `captchaText`
- `trafficSource`：包含 UTM 参数和 `document.referrer`
- `locale`
- `pageUrl`

`phone` 与 `phoneOrWechat` 同时发送，确保后台的通知模板和留言详情都能
显示现有“电话 / 微信”输入。额外的 `locale` 和 `pageUrl` 作为普通留言
元数据保存，不要求后台新增字段。

### 访客统计

官网使用后台现有的百度统计方案：

1. 在同一百度统计账户中登记 `jotoglobal.com`。
2. 把该站点返回的跟踪 ID 作为生产构建变量
   `VITE_BAIDU_TONGJI_ID` 注入官网。
3. 官网加载百度统计脚本并记录页面访问。
4. 表单提交成功后记录统一的转化页面和“表单提交”事件。
5. 后台通过现有百度统计接口动态读取账户中的站点，新站无需修改后台
   仓库即可出现在访客统计站点列表中。

未配置跟踪 ID 时统计模块必须静默停用，不阻塞页面渲染或表单提交。

### 健康巡检

通过 `admin.jotoai.com` 现有“站点管理”运行时配置新增：

- 站点 ID：`jotoglobal`
- 站点名称：`JOTO TECH`
- 站点 URL：`https://jotoglobal.com`
- 描述：`JOTO TECH 全球企业 IT 解决方案官网`

后台巡检和每日报告从运行时站点配置动态读取 URL，因此登记后即可自动
覆盖该站点，不需要修改后台仓库中的硬编码站点集合。

留言仍使用通用 `/api/contact` 路径，并在统一留言列表中按
`jotoglobal.com` 来源显示；不依赖后台的站点专用
`/api/:site/contact` 路径。

## 官网改动

### 联系表单

`ContactForm` 增加可刷新验证码：

- 页面首次渲染时加载验证码。
- 验证码加载失败时显示三语言错误，并提供重试按钮。
- 验证码图片可点击刷新，另提供具备可访问名称的刷新按钮。
- 提交前要求验证码输入不为空。
- 每次提交成功或失败后刷新验证码，防止复用已消费或已过期的验证码。
- 后台返回可读错误时显示经过映射的三语言提示；未知错误使用现有通用
  失败提示和销售邮箱兜底。
- 成功后清空表单，保留现有成功反馈。

### 统计模块

新增独立、无界面的百度统计加载模块：

- 只在浏览器环境且存在 `VITE_BAIDU_TONGJI_ID` 时加载一次。
- 脚本异步加载，失败不抛出到页面。
- 支持 SPA 路由变化时记录标准化路径。
- 表单成功时记录 `/poc-submitted` 虚拟页面和站点标识为
  `jotoglobal` 的转化事件。
- 测试环境不加载外部脚本。

### Nginx

生产 Nginx 配置调整：

- `/api/captcha` 转发到
  `https://admin.jotoai.com/api/captcha`。
- `/api/contact` 转发到
  `https://admin.jotoai.com/api/contact`。
- 为 HTTPS 上游启用正确的 SNI，TLS 名称使用
  `admin.jotoai.com`。
- 上游请求的 `Host` 使用 `admin.jotoai.com`，确保命中正确的 HTTPS
  虚拟主机；`X-Forwarded-Host` 使用原始官网主机名，供后台识别来源。
- 继续传递真实客户端 IP、协议和请求 ID。
- 联系提交继续使用现有按 IP 限流、16 KB 请求体限制、短连接和禁止
  缓存策略。
- 验证码接口禁止缓存，并设置独立的短超时。
- 旧 `127.0.0.1:9000` 服务不再接收生产 `/api/contact` 请求。

本地开发环境把 `/api/captcha` 和 `/api/contact` 代理到可配置的统一
后台地址；自动化组件测试使用请求模拟，不依赖真实后台。

## 安全与隐私

- 百度跟踪 ID 是公开站点标识，不作为密钥处理；后台管理员令牌、百度
  访问令牌和邮件凭据不得进入官网构建产物或 Git。
- 浏览器只访问官网同源 API，不接触后台管理员认证接口。
- Nginx 不记录表单请求体或验证码内容。
- 表单继续使用前后端字段校验、隐藏蜜罐、验证码和按 IP 限流。
- `trafficSource` 只记录页面 URL、UTM 参数和浏览器已提供的 referrer，
  不采集指纹、精确位置或额外身份信息。
- 统计脚本仅在生产跟踪 ID 存在时启用。

## 错误处理

- 验证码上游不可用：验证码区域显示加载失败，禁用提交并允许刷新。
- 验证码错误或过期：保留用户已填写的业务字段，显示对应提示并自动
  换一张验证码。
- 留言上游超时或 5xx：显示通用失败提示和销售邮箱，不回退到旧邮件
  服务，避免后台与邮件状态不一致。
- 百度统计失败：静默忽略，不影响业务功能。
- 巡检配置失败：不影响官网上线，但不能把“统一巡检”标记为验收通过，
  必须完成运行时站点登记后再次检查。

## 测试与验证

### 自动化测试

- 验证码首次加载与刷新。
- 验证码失败、为空、错误和过期。
- 表单字段到后台字段的兼容映射。
- 合法提交成功、后台验证失败、网络失败和 5xx。
- 提交成功后刷新验证码、清空表单并触发转化事件。
- 统计 ID 缺失时不加载脚本。
- 统计 ID 存在时只加载一次，并能记录 SPA 页面与转化。
- 英文、中文和波斯语状态文案完整。
- 现有组件、路由、SEO 和生产构建测试保持通过。

### 部署验证

- 部署前运行生产构建和全部自动化测试。
- 在服务器上先运行 `nginx -t`，再平滑重载。
- 验证 `/api/captcha` 返回可显示的验证码。
- 经用户允许后提交一条明确标记为部署验收的生产测试留言。
- 在 `admin.jotoai.com` 留言管理页确认来源、联系人、留言正文和时间。
- 确认统一后台只发送一封邮件，旧本地服务没有产生第二封通知。
- 确认百度统计站点列表包含 `jotoglobal.com`，并在数据延迟窗口后出现
  访问或转化。
- 确认后台站点管理包含 `jotoglobal`，健康巡检返回 2xx、页面内容正常
  且延迟可见。
- 复查服务器上的其他站点和后台服务未受影响。

浏览器生产验收若遇到验证码，必须由用户明确同意后再完成测试验证码，
不得绕过验证码。

## 发布与回滚

发布顺序：

1. 完成并验证前端、统计模块和 Nginx 配置。
2. 在百度统计账户登记官网并准备生产跟踪 ID。
3. 在统一后台的站点管理中登记 `jotoglobal`。
4. 部署新的官网静态产物和 Nginx 片段。
5. 检查 Nginx 后平滑重载。
6. 完成留言、访客统计和巡检的生产验收。

回滚时恢复上一版官网静态产物和 Nginx 片段，使
`/api/contact` 暂时重新指向本机旧服务。后台已存储的留言和站点运行时
配置不删除，避免破坏已有数据；如需撤销后台运行时配置，必须单独确认。

## 验收标准

- 后台仓库没有任何文件、提交或部署变更。
- 官网联系表单必须通过后台验证码才能提交。
- 一条合法留言只在统一后台落库一次，并且只触发一组统一通知。
- 留言管理页显示 `jotoglobal.com` 来源和完整联系人信息。
- 旧本地联系服务不再收到生产提交。
- `jotoglobal.com` 出现在后台访客统计站点列表中。
- `jotoglobal` 出现在后台站点运行时配置和健康巡检结果中。
- 三语言表单、移动端、键盘操作、RTL、错误提示和邮箱兜底正常。
- 全部自动化测试、生产构建、Nginx 配置检查和生产验收通过。
