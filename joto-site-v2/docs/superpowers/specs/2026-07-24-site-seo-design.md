# JOTO TECH 全站 SEO 优化设计

日期：2026-07-24

## 背景

JOTO TECH V2 是一个基于 Vite、React 与 TypeScript 的三语言企业官网。英文路由不使用语言前缀，中文使用 `/zh/`，波斯语使用 `/fa/`。站点包含首页、关于、联系、博客列表、博客文章、五类解决方案，以及各技术厂商详情页。

当前实现只在 `index.html` 中提供一套全站通用标题与描述，并由 `I18nProvider` 根据语言覆盖首页级标题和描述。不同路由没有独立的 canonical、hreflang、社交分享元数据或结构化数据，也没有正式的站点地图、抓取规则和未知路由处理。这会削弱搜索引擎对页面主题、语言版本和网址关系的理解。

## 目标

- 以 `https://jotoglobal.com` 为唯一正式主域名。
- 采用中文优先、英文和波斯语完整覆盖的内容策略。
- 为所有公开页面提供独立、准确且可维护的 SEO 元数据。
- 建立三语言 canonical 与 hreflang 关系。
- 增加适合企业官网、解决方案页和博客文章的结构化数据。
- 明确控制公开页面、预览页面和未知路由的收录行为。
- 保持当前 SPA 部署方式，并为未来预渲染保留清晰的数据边界。
- 不改变现有视觉设计，不引入未经确认的商业事实、资质或合作等级。

## 非目标

- 本轮不迁移到 Next.js、Astro 或其他服务端渲染框架。
- 本轮不实施全站静态预渲染。
- 本轮不购买关键词、建立外链或代为提交搜索引擎站长平台。
- 本轮不重写大段正文，也不改变现有页面版式。
- 本轮不承诺具体自然搜索排名或收录时间。

## 方案选择

采用“完整站内 SEO”方案：

- 建立统一的页面级 SEO 配置与渲染层。
- 补齐技术 SEO、内容 SEO、结构化数据、站点地图和收录控制。
- 继续使用当前 React SPA 和 Sites Worker 回退。
- 让路由清单与 SEO 数据保持独立，方便后续预渲染复用。

未选择仅补基础元数据的轻量方案，因为它不能充分表达多语言和大量详情页之间的关系。未在本轮直接实施预渲染，是为了避免在尚未稳定 SEO 数据模型前扩大构建与部署改动。

## SEO 架构

### 页面描述模型

新增独立的 SEO 模块，根据当前语言、标准化路由和页面内容生成页面描述对象。该对象包含：

- 页面标题
- meta description
- canonical URL
- robots 指令
- Open Graph 类型、标题、描述、网址和图片
- Twitter Card 字段
- 三语言 alternate URL 与 `x-default`
- 页面所需的 JSON-LD 节点

页面组件只提供业务内容或页面身份，不直接操作 `<head>`。SEO 渲染组件负责创建、更新和清理动态标签，避免路由切换后残留前一页面的数据。

`I18nProvider` 继续负责语言识别、文本方向与语言内容，不再负责路由级页面标题和描述。

### 路由分类

公开并允许索引的页面：

- 首页 `/`
- 关于 `/about`
- 联系 `/contact`
- 博客列表 `/blog`
- 所有有效博客文章 `/blog/:slug`
- 五类解决方案 `/solutions/:category`
- 所有有效厂商详情 `/solutions/:category/:partner`
- 上述页面对应的 `/zh/` 和 `/fa/` 版本

不允许索引的页面：

- `/preview/customer-logo-wall`
- `/preview/solution-capability-icons`
- 对应的多语言预览路径
- 任何无法匹配有效内容的未知路径

预览页面使用 `noindex, nofollow`。未知路径显示明确的 404 页面并使用 `noindex, nofollow`，同时不生成公开页面的 canonical 或结构化数据。

### URL 规则

- 主域名固定为 `https://jotoglobal.com`。
- 英文是默认版本，不使用语言前缀。
- 中文使用 `/zh` 前缀。
- 波斯语使用 `/fa` 前缀。
- canonical 指向当前页面当前语言的绝对网址。
- 每个可索引页面提供英文、中文、波斯语 hreflang。
- `x-default` 指向对应英文网址。
- canonical 和 alternate URL 不包含查询参数或锚点。
- 根路径以 `/` 结尾；其他路径统一不使用末尾斜杠，避免重复网址。

## 内容策略

### 中文优先

中文标题和摘要优先覆盖企业采购与技术服务搜索意图，同时保持自然表达。重点主题包括：

- 企业 IT 解决方案
- IT 系统集成
- 企业网络解决方案
- 网络安全集成与运维
- 服务器、存储、备份与灾备
- Microsoft Teams 电话与企业协作
- 视频监控、门禁与物理安防
- IT 咨询、部署和托管服务
- 中国本地交付与全球项目支持

英文与波斯语保持与中文页面相同的业务意图，但按照各自语言自然撰写，不采用逐字翻译。

### 页面标题策略

- 首页：核心业务 + 服务地域 + 品牌。
- 关于页：公司定位 + 上海起点 + 品牌。
- 联系页：咨询或获取方案 + 品牌。
- 博客列表：企业 IT 洞察或案例 + 品牌。
- 博客文章：文章标题 + 品牌。
- 解决方案分类：解决方案主题 + 集成与服务能力 + 品牌。
- 厂商详情：厂商品牌 + 技术领域 + JOTO 实施与支持。

标题保持唯一，优先让核心主题出现在前半段。品牌名通常置于末尾。标题长度以搜索结果可读性为准，不机械截断具有必要业务含义的词组。

### Meta description 策略

每个公开页面使用与页面内容一致的独立摘要，说明：

- 提供什么服务或信息；
- 适合什么企业场景；
- JOTO 的设计、实施或持续支持能力；
- 在内容自然时体现中国本地与全球交付。

摘要不堆叠关键词，不使用无法验证的领先、第一或保证性表述。

### 可见内容调整

允许微调首页、解决方案页、厂商详情页、博客页、关于页和联系页的开场摘要，使页面主题与搜索意图更明确。调整遵循以下限制：

- 不改变事实范围。
- 不新增未经确认的合作认证、客户授权或服务覆盖承诺。
- 不改变视觉布局和主要品牌语气。
- 不为了关键词密度重复同义表达。

## 元数据与分享体验

所有公开页面提供：

- `<title>`
- `<meta name="description">`
- `<meta name="robots">`
- `<link rel="canonical">`
- 三个语言 alternate link
- `x-default` alternate link
- `og:type`
- `og:site_name`
- `og:title`
- `og:description`
- `og:url`
- `og:locale` 与可用的 alternate locale
- `og:image`、图片替代文本和图片尺寸
- `twitter:card`
- `twitter:title`
- `twitter:description`
- `twitter:image`

博客文章使用 `article` Open Graph 类型，其他页面使用 `website`。

默认分享图使用正式品牌分享图；博客文章优先使用文章主图。所有分享图输出绝对 URL。

## 结构化数据

### 全站实体

首页提供 `Organization` 和 `WebSite`：

- 企业名称与英文名称
- 正式网址
- 品牌 Logo
- 联系方式
- 上海总部或已确认的办公信息
- 可确认的服务区域

只使用站内已确认数据，不补猜测性的社交账号、成立信息或资质字段。

### 页面结构

内部页面提供 `BreadcrumbList`，反映页面在首页、解决方案、博客或厂商层级中的位置。

博客文章提供 `Article`：

- 标题
- 摘要
- 主图
- 发布日期
- 修改日期（只有内容数据明确提供时才输出）
- 作者或发布组织
- 主页面网址

关于页可提供 `AboutPage`，联系页可提供 `ContactPage`，其他普通页面使用与内容相符的 `WebPage`。

多个 JSON-LD 节点使用 `@graph` 组织，并通过稳定的 `@id` 建立企业、网站、页面和文章之间的关系。

## 站点地图与抓取规则

### sitemap.xml

构建阶段根据公开路由清单生成 `sitemap.xml`：

- 包含所有有效公开页面的三语言网址。
- 每个网址带对应的 alternate language links。
- 不包含预览页、未知路由、查询参数或锚点。
- 博客文章只有在内容数据中存在时才进入站点地图。
- `lastmod` 仅在有可信内容日期时输出，不用构建时间伪造更新时间。

### robots.txt

`robots.txt`：

- 允许抓取公开站点。
- 明确阻止 `/preview/`、`/zh/preview/` 与 `/fa/preview/`。
- 指向 `https://jotoglobal.com/sitemap.xml`。

页面级 `noindex` 仍作为预览页和 404 页的主要收录控制；robots 规则是额外保护。

## 404 与错误处理

当前未知路径会回退到首页内容。优化后，路由无法匹配有效页面时显示品牌化 404 页面：

- 明确说明页面不存在。
- 提供返回首页、解决方案、博客和联系页的链接。
- 保持当前语言与文字方向。
- 设置 `noindex, nofollow`。
- 不加入站点地图。

Sites Worker 继续提供 SPA 文件回退。由于 Worker 当前把未知非文件请求返回 `index.html`，实际 HTTP 状态可能仍为 200；页面级 404 与 noindex 可以先防止错误收录。未来预渲染或边缘路由升级时，再为未知路径返回真实 HTTP 404。

## 图片与语义结构

- 为可索引内容图片保留准确且与上下文相关的 alt 文本。
- 装饰性和重复轮播图片使用空 alt，避免重复朗读与关键词噪声。
- 非首屏图片保持懒加载，首屏主图按性能需要优先加载。
- 可确定尺寸的图片补充宽高或稳定的纵横比，减少布局偏移。
- 每个页面保留一个描述主要主题的 `<h1>`。
- 区块标题按结构使用 `<h2>` 和 `<h3>`，不为视觉大小跳级。
- 关键导航使用真实 `<a href>`，保持可抓取内部链接。

## 性能与字体边界

SEO 实施不得显著增加首屏 JavaScript。结构化数据和元数据使用轻量组件或原生 DOM API，不引入大型 head 管理依赖。

当前 CSS 仍从 Google Fonts 加载部分字体，这可能影响部分地区的加载稳定性。本轮只记录为后续性能优化项；除非实施过程中发现它直接阻塞关键渲染，否则不扩展为字体迁移任务。

## 测试与验收

### 自动测试

- 各语言首页生成正确的标题、描述和语言属性。
- 关于、联系、博客列表、文章、解决方案和厂商详情生成独立元数据。
- canonical 与当前语言路由一致。
- hreflang 覆盖 `en`、`zh-CN`、`fa-IR` 和 `x-default`。
- Open Graph 与 Twitter URL、标题、描述和图片完整。
- JSON-LD 可解析并包含对应页面所需类型。
- 预览页使用 `noindex, nofollow`。
- 未知路由显示 404 并使用 `noindex, nofollow`。
- sitemap 覆盖全部公开三语言路由，且不包含预览或未知路径。
- robots 文件指向正式 sitemap。
- 原有路由、语言切换和内容测试继续通过。

### 构建验证

- `npm test -- --run`
- `npm run build`
- 检查生产构建中的 `robots.txt` 和 `sitemap.xml`
- 检查代表性英文、中文和波斯语页面的元数据
- 检查至少一个博客文章、解决方案分类、厂商详情、预览页和未知路径

### 内容质量检查

- 标题和描述没有重复。
- 标题、描述与页面可见内容一致。
- 中文核心业务主题自然出现。
- 没有关键词堆砌。
- 没有新增无法验证的业务事实。
- 页面标题层级清晰。
- 内部链接不存在明显断链。

## 实施边界与文件组织

预计改动集中在：

- 新的 SEO 页面描述、URL 和结构化数据模块
- SEO head 渲染组件
- 应用路由的页面身份与 404 分支
- 三语言内容或 SEO 文案映射
- 构建阶段的站点地图生成脚本
- `public/robots.txt` 与品牌分享图
- SEO、路由、站点地图和 404 测试

不修改现有客户 Logo 测试中的用户改动，不清理 `output/`，不进行无关组件重构。

## 后续升级路径

如果上线后需要提升非 JavaScript 抓取兼容性，可在不重写 SEO 数据层的前提下增加预渲染：

1. 复用公开路由清单枚举所有语言网址。
2. 在构建时为每个网址输出完整 HTML。
3. 复用相同页面描述对象写入静态 `<head>`。
4. 更新 Worker，使预渲染路径返回对应 HTML，未知路径返回真实 HTTP 404。

该升级不属于本轮实施范围。
